零、先说我是什么样的人

我不是计算机科班出身，是建筑工程出身。所以我的路子和科班不一样：

  • 我是带着问题去学技术的，不是先学理论再找用途
  • 我做的每个东西都是为了解决一个真实的麻烦，不是为了练手
  • 我习惯一个人把整条链走完：从想法、设计、写代码、部署、运维到出问题自己修

这条路的结果是：单点深度不如专职的人（比如我不如专职前端做设计，不如算法工程师写算法），但端到端的完整能力是稀缺的。一个产品从零到上线，绝大多数人只负责其中一段。

具体证据： - 一套 AI 内容生产平台，64,752 行 Python、2,484 个路由、626 个模板、32 张数据表、11 个生产步骤，从第一行代码到线上运维全是我 - 21 个真实生产故障的完整复盘，公开在 GitHub（ai-drama-pipeline 仓库） - 一台服务器上长期跑 10+ 个独立 AI Agent 实例 - 单卡 24G 显卡上跑通了画图、图生视频、口型同步、语音合成全套开源模型

一、一句话概括

我能把 AI 从「demo 跑通了」做到「能上线、能收钱、不天天出故障」。

拆成三句话： 1. 能一个人把产品做上线（前端、后端、数据库、部署、运维全会） 2. 处理过大量真实生产故障（不是只在学校里写过作业） 3. 知道 AI 项目哪里烧钱、怎么省（成本结构清楚，不是只会调 API）

一套完整的 AI 内容生产平台（AI 短剧工坊），把「一段故事」变成「一集成片」的全流程自动化：

环节 我实现的东西
剧本 分集大纲 → 台词 → 分镜表，AI 生成 + 人工可改
角色 角色注册表（cast.json）、六视图标准照生成、跨镜头一致性
出图 每个镜头的首帧图，接可灵/千问/ComfyUI
出视频 图生视频、运镜、时长控制、废片检测
配音 多角色音色、逐句时间轴、语速校准
字幕 逐句对齐、双行合并、烧字幕

计费 积分扣费、订单、退款（含赠送积分追踪）

规模：64,752 行 Python / 14,574 行 JS / 626 个模板 / 2,484 路由 / 32 张表 / 11 个生产步骤

会用的工具

Flask、FastAPI、PostgreSQL、Alembic、Jinja2、esbuild、Celery/线程任务、systemd、nginx、Docker

能帮别人解决什么

  • AI 功能做出来了但不敢上线 → 我补齐计费、权限、并发、重试、部署
  • 生成任务排不上队 / 卡死 / 进度永远 0% → 我改队列架构
  • 多人同时用就崩 → 我处理并发和 gunicorn 多进程状态问题

边界

  • 不是算法工程师，不做模型训练和论文复现
  • 不做纯设计（能写可用界面，做不出惊艳视觉）

领域 2｜后端工程

做过什么

  • API 设计：2,484 个路由，覆盖认证、任务、计费、文件、管理后台
  • 数据库设计：32 张表，从 SQLite 迁到 PostgreSQL（含 Alembic 迁移）
  • 并发控制：多 worker 下的任务队列，用 SELECT FOR UPDATE SKIP LOCKED 防重复消费
  • 认证体系：密码 + 短信验证码双登录，CSRF 防护，管理员权限分离
  • 文件服务：nginx X-Accel-Redirect 加速，且区分管理员/普通用户的目录权限
  • 故障处理：gunicorn 多进程内存不共享、时区统一、缓存失效、连接池配置

真实故障（可以脱稿讲的）

  1. 进度永远 0%：gunicorn -w 4 四个进程各自有内存字典，任务建在 #2，轮询进 #3 查不到。改成落数据库后顺手解决了重启丢状态。
  2. 限流失效：内存计数器在 4 个进程各算各的，配的 100 次/分实际放行 400 次。
  3. 支付回调 302：NOTIFY_URL 多写了 blueprint 前缀，微信服务器跳转后丢了 POST body。
  4. 时区错乱：UTC 和本地时间混在一张表，同一天的记录日期差一天。

能帮别人解决什么

  • 系统越改越乱不敢动 → 先做依赖和数据流审计，再按风险排序小步重构
  • 上线才出现的 bug，本地复现不出来 → 这是我最有经验的一类
  • 多个人/多台机器部署，状态对不上 → 外置状态到 DB 或 Redis

领域 3｜AI 模型部署与调优（本地 + 云端）

做过什么

在单卡 24G 显存上跑通了一整套开源模型，并且知道每个模型吃多少显存、什么参数会崩：

类型 模型 实测数据
画图 FLUX.1 dev fp8 + IP-Adapter + ControlNet 24G 卡可跑，出图约 20-40 秒
图生视频 Wan 2.1、SVD 512p 短片段可行，第 2 秒易崩脸
口型同步 Sonic、LatentSync、Wav2Lip 4.8 秒音频要跑 205 秒
语音合成 IndexTTS（154 个音色 + 克隆）、CosyVoice 常驻占 6.7G
语音识别 whisper.cpp（CUDA 编译） 中文优先，常驻 2.3G
文本 llama.cpp / vLLM，27B / 32B 量化模型 双卡或量化下沉

关键经验（这些是踩坑换来的）

  • 显存不够不报 OOM，而是慢十倍然后给你一张废图 —— 因为它在拿内存当显存搬权重
  • 可用显存 = 单卡容量 − 常驻服务占用（我这台常驻 TTS 6.7G + ACE-Step 3.2G + ComfyUI 2.5G + whisper 2.3G ≈ 15G）
  • 权重 ≤ 可用显存 × 0.8 才安全
  • 双卡 ≠ 双倍显存，模型切分有额外开销
  • RTX 5090（Blackwell）需要新 CUDA 版本，老框架直接编译失败

能帮别人解决什么

  • 想本地跑 AI 但不知道买什么卡 → 按任务倒推显存需求
  • 本地跑通了但太慢/画质差 → 判断是显存不足还是参数问题
  • 云端 API 太贵 → 算清楚哪些任务该本地、哪些该上云

领域 4｜音视频处理（ffmpeg 全链路）

做过什么

  • 视频拼接与裁剪：按镜头时长智能裁剪，解决「AI 视频比音频长」的累计误差
  • 黑帧/废帧检测：逐帧分析，拼接前清理

能帮别人解决什么

  • 字幕一闪而过或对不上口型 → 时间戳重算
  • 音量忽大忽小 → 分段标准化

领域 6｜消息机器人与自动化运维

做过什么

  • 飞书 Bot 集群：一台机器跑 10+ 个独立实例，profile 隔离、systemd 托管、Docker 沙箱、掉线自恢复、版本升级
  • 企业微信接入：AI Bot 长连接模式（绕开公网回调），扫码登录、凭据加密、消息收发
  • 邮箱自动化：IMAP 读取、规则过滤、自动归档、定时巡检（每 4 小时）
  • 定时任务体系：cron 任务管理、任务台账、失败告警、避免重复执行
  • 微信生态：小程序登录调试、微信支付接入、公众号/客服

关键经验

  • 在 gateway 进程内重启 gateway 会杀掉自己 → 用一次性 cron 任务脱离进程树

能帮别人解决什么

  • 想让 AI 接入公司内部沟通工具 → 飞书/企微/钉钉都能接
  • 客服重复问题太多 → AI 自动回复 + 人工接管

领域 9｜支付与商业化闭环

做过什么

  • 微信支付 v3：Native 扫码支付，签名验证、回调验签、AES-GCM 解密
  • 积分计费系统：扣费规则单一真相源（DB 驱动），步骤单价可配
  • 订单与退款：实付/赠送积分分离追踪，退款金额上限校验
  • 充值流程：下单 → 支付 → 回调 → 到账 → 赠送，全链路幂等
  • 对账：流水与余额一致性校验

踩过的三个坑（都能讲成故事）

  1. NOTIFY_URL 多写前缀 → 微信回调 302，POST body 丢失
  2. 公钥不匹配 → 401，以为密钥错了实际是证书版本
  3. APIv3 密钥不匹配 → AES-GCM 解密失败，报错信息完全不指向真正原因

能帮别人解决什么

  • 想收钱但不知道怎么接 → 微信支付全流程
  • 退款总是算错 → 实付/赠送分离 + 幂等设计
  • 计费规则散在代码里改不动 → 抽到数据库

领域 10｜浏览器自动化与逆向

做过什么

  • Playwright 全自动发布：登录态持久化（扫码一次长期有效）、自动填表、自动发文章到掘金和 CSDN
  • CDP 接管模式：用户手动扫码登录，程序控制同一个浏览器窗口，不碰密码和验证码
  • 绕过 WAF：识别「无头浏览器指纹」，改用有头模式（Xvfb 虚拟显示）
  • 逆向工具链：jadx（APK→Java）、apktool（重打包）、Ghidra（二进制反编译）、radare2、frida（动态 hook）、mitmproxy（抓包）
  • 爬虫：招标公告、企业信息、视频数据抓取

关键经验

  • curl 能通但浏览器 403 → 是指纹问题，不是 IP 问题，换代理没用
  • JS 的 .click() 不触发框架事件委托 → 必须用真实鼠标坐标点击
  • 点不动的按钮，先去抓服务端错误（expect_response），不要瞎试 UI

能帮别人解决什么

  • 每天手工在网站上做重复操作 → 自动化（发布、填表、抓数据）
  • 想知道某个 App 怎么实现的 → 拆包分析（合法用途：竞品功能研究）

五、三个版本的自我介绍

版本 A｜30 秒（电梯里遇到）

我做 AI 应用落地的。一个人写过一套六万多行的 AI 内容生产平台，从剧本到成片全自动，用户、计费、支付、客服都是我自己做的。强项是让 AI 功能真正上线跑稳，还有把成本压下来。

版本 B｜2 分钟（正式面试开场）

我建筑工程出身，转行做开发，现在是独立开发者。

我最主要的作品是一套 AI 内容生产平台：输入一段故事，自动生成分集大纲、分镜、角色形象、每个镜头的画面和视频，再配音、配字幕、合成成片。整个系统 64,752 行 Python、2,484 个接口、32 张数据表，从第一行代码到线上运维都是我一个人。

里面最难的不是调 AI 接口，是工程问题：多进程下的任务状态、支付的幂等、生成任务排队和失败重试、成本控制。我把踩过的 21 个真实故障全写成了复盘，公开在 GitHub 上。

我的定位是：能把 AI 从 demo 做到上线的工程人。会调 API 的人很多，能让它稳定跑一年的人少。
